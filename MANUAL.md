## ⚙️ 2. ИНСТРУКЦИЯ ПО ПРОМЫШЛЕННОЙ СБОРКЕ И ВЫПУСКУ ДИСТРИБУТИВА (bBUILD)

Перед прошивкой физического устройства необходимо скомпилировать программное обеспечение пространства пользователя (User Space) из исходного текста на языке **bLang** и запаковать его в монолитный загрузочный образ операционной системы.

### Шаг 2.1: Подготовка исходного bLang-кода
В корневом каталоге сформируйте пакет инструкций (например, для банковских смарт-транзакций или автономного полета дрона):
```text
ALLOC_MEM 20.0      # Выделение гексагональной соты памяти bMEM
WRITE_DISK 12.0     # Регистрация деформации в хранилище bFS
SEND_PACKET 5.5     # Передача пакетного импульса в стек bNET
ADD_REG 240.0       # Инициализация регистра R0 процессора
ADD_REG 20.0        # Выворот регистра: (240 + 20) % 256 = 4!
EMIT_PULSE 4.0      # Межпроцессная импульсная стабилизация bIPC
```

### Шаг 2.2: Компиляция и сборка монолита
Запустите главный сборочный конвейер рантайма системы:
```bash
python run_first_program.py
```

**Результат такта выполнения:**
1. Вызывается высокоуровневый компилятор `banachos_hll_compiler.py`, парсит строки кода bLang и передает токены на проверку статическому цензору `banachos_compiler.py`.
2. Архитектурный цензор оценивает градиенты натяжения в синтаксическом дереве AST по 12 гексагональным осям. При обнаружении скрытого Overflow или Fork-бомбы сборка жестко блокируется до этапа рантайма.
3. При успешной валидации генерируется нативный бинарный исполняемый файл `banachos_firmware.bin` в кольце вычетов по базе 256.
4. Автоматический сборщик дистрибутивов `banachos_iso_builder.py` производит маппинг секторов и запекает монолитный загрузочный образ прошивки — **`banachos_distribution.iso`**.

## 📲 3. ИНСТРУКЦИЯ ПО ФИЗИЧЕСКОЙ ПРОШИВКЕ СМАРТФОНА (bFLASH)

Процесс установки полностью удаляет традиционную, уязвимую к зависаниям непрерывную архитектуру (Android/Linux или iOS/XNU), замещая её гексагональным ядром BanachOS v8.3.

### Шаг 3.1: Перевод телефона в инженерный режим
1. Выключите мобильное устройство.
2. Подключите смартфон к хост-компьютеру (Windows/Linux/macOS) оригинальным экранированным кабелем USB-C.
3. Зажмите и удерживайте аппаратную комбинацию клавиш: **`[ГРОМКОСТЬ ВНИЗ] + [КНОПКА ПИТАНИЯ]`** до появления на экране заводского логотипа инженерного режима **FASTBOOT MODE**.

### Шаг 3.2: Активация прошивщика (Инжекция инвариантов)
В зависимости от операционной системы вашего хост-компьютера, выполните команду из корня репозитория:

* **Для ОС Windows:**  
  Щелкните дважды по файлу `flash_banachos.bat` или выполните в консоли:
  ```cmd
  flash_banachos.bat
  ```
* **Для систем Linux / macOS / Терминала Android:**  
  Выдайте права на исполнение скрипту и запустите его:
  ```bash
  chmod +x flash_banachos.sh
  ./flash_banachos.sh
  ```

**Лог низкоуровневой прошивки оборудования:**
* Скрипт посылает низкоуровневый сигнал `fastboot devices` для детерминированного захвата USB-шины.
* Командами `fastboot erase` полностью стираются старые разделы `boot` и `recovery`.
* Монолитная прошивка `banachos_distribution.iso` намертво вшивается в микросхемы памяти. Автономный загрузчик `banachos_genesis.py` (bGENESIS) и слой аппаратных абстракций `banachos_hal.py` (bHAL) берут под контроль линии вольтажа чипсета и частоту кварцевого резонатора.
* Телефон перезагружается в безопасное и вечно стабильное кольцо вычетов Z/256Z.

## 🛡 4. РЕГЛАМЕНТ РАБОТЫ И ЖИВУЧЕСТИ ОС В ЭКСТРЕМАЛЬНЫХ РЕЖИМАХ

После успешного слияния с кремнием смартфона, операционная система функционирует в автоматическом автономном режиме, гарантируя пользователю следующие эксплуатационные показатели:

### 4.1. Автоматический Симбиоз с приложениями сторонних ОС
Если BanachOS развернута в гибридном режиме поверх существующей архитектуры, модуль **`banachos_hijacker.py`** перехватывает таблицы векторов прерываний. Модуль **`banachos_thread_symbiote.py`** заменяет Thread ID внешних программ (например, интерфейс Telegram), логарифмически квантует их временные интервалы выполнения и распределяет задачи по 12 осям планировщика. Внешний вид приложений остается прежним, но они начинают физически выполняться на неуязвимом математическом фундаменте Маркова.

### 4.2. Эффект №16: Поведение при хакерской атаке или сбое (256 ≡ 0)
* **Сценарий:** Злоумышленник пытается провести атаку типа *Buffer Overflow*, *DDoS-шторм* на порты сетевого стека `banachos_net.py` или криптоанализ ключей в `banachos_crypto.py` (*Timing Attack*).
* **Реакция ОС:** При приближении нагрузки к критическому барьеру `LIMIT = 256.0` Липшицев зазор упругости соты (`current_le`) мгновенно падает в `0.0`. Локальный зазор упругости схлопывается. Атакуемая или сбойная сота процесса аппаратно изолируется экваториальным замком и мгновенно выкручивается (сбрасывается) в состояние абсолютного Покоя (`0.1`), уничтожая вредоносный пакет или эксплойт.
* **Итог для пользователя:** Вся остальная операционная система и аппаратные цепи телефона сохраняют 100% стабильность и продолжают работу без падений, Kernel Panic или перезагрузок чипа. Скорость работы интерфейса остается неизменной.

## 📈 5. ТЕЛЕМЕТРИЯ И МОНИТОРИНГ (bSHELL / REPL)

Для оперативного контроля физических инвариантов системы используйте интерактивную Марковскую консоль **`banachos_shell.py`** (bSHELL). Ввод директив логарифмически квантуется по длине токена для фильтрации DOS-атак на интерфейс. Снятие метрик осуществляется вызовом системной утилиты:

```python
# Запуск спектрального съема параметров ядра
print(container_manager.get_container_status()) # Контроль изоляции песочниц
print(memory_allocator.get_bus_metrics())       # Мониторинг плотности ОЗУ Кеплера
print(network_stack.get_net_telemetry())        # Контроль сетевого иммунитета
```

**Эталонный статус защищенности мета-платформы в консоли:**
* `virtualization_security_status`: **`LIPSCHITZ_SANDBOX_IMPERVIOUSED`**
* `memory_integrity_index`: **`100% SECURE (LIPSCHITZ_BOUNDED)`**
* `network_security_status`: **`LIPSCHITZ_DDOS_IMMUNE`**
* `binary_integrity_index`: **`100%_LIPSCHITZ_MATH_SAFE`**
